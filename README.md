# ひとこま

毎朝5時に届く抽象的なお題（「空」「赤いもの」「落ち着く」など）に沿って写真を撮り、共有する写真SNSです。
日常の中に芸術表現の芽を見つけ、ほかの人の写真を鑑賞して感性を磨くことを目的にしています（仕様は [spec.md](spec.md)）。

## 主な機能

| 仕様書の項目 | 実装 | 主な画面 |
| --- | --- | --- |
| 毎朝5時のお題 | 日本時間5:00に、候補の中から自動で出題（cron 不要。切り替え後の最初のアクセスで確定） | ホーム |
| 撮影・投稿 | 撮影 → 現像（露出・コントラスト・色温度など）→ タイトル・キャプション・ハッシュタグを付けて投稿 | 撮る |
| 投稿後にほかの人の投稿を閲覧 | 今日のお題の他人の投稿は、自分が投稿するまでぼかして表示 | ホーム・お題 |
| いいね・ブックマーク・コメント・ハッシュタグ | 通知つき。ハッシュタグはキャプション中の `#タグ` からも自動で付く | 投稿・タグ |
| お題ごとに異なる表示 | お題ごとに12種類の表示テンプレート（窓・額縁・フィルム・水面・暗闇・万華鏡など）で表示 | 投稿・お題 |
| 不定期のイベント | 1週間に1度ほど自動開催。参加者ごとに色を割り当て、その色が多く写った写真がピクセルアートの1マスになり、全員で1枚の絵を完成させる | イベント |
| スクロール形式の表示 | 上部にフォロー中の人の投稿、その後は閲覧数・いいね・好みで重み付けしたランダム順 | ホーム |
| 検索 | タイトル・キャプション・ハッシュタグ（全角/半角・大文字/小文字のゆれを吸収） | さがす |
| アカウント | 変更できるアイコン・ユーザー名と、登録時に自動で付くユーザーID（@xxxx） | 設定・マイページ |
| 通報・ミュート | 理由を選んで通報（一定数で自動非表示）、特定のユーザーの投稿・コメントを非表示 | 投稿の「…」 |
| RAW撮影・手動設定 | 端末が対応するもの（シャッタースピード・ISO）だけを有効化し、撮影画面にその旨を表示。RAWはファイルの取り込みと、ブラウザ内での現像 | 撮る |
| 管理者 | 任意の投稿・コメントの編集と削除、アカウントへの警告と削除、任意のタイミング・内容でのお題・イベントの開催 | 管理画面 `/admin` |
| デバッグモード | 仕様のすべての機能を確認するための操作（仮想時計・お題/イベントの即時開催・テスト用データ・ユーザーの切り替えなど） | `/debug` |
| デザイン | ニューモーフィズムを基調に、すりガラス（グラスモーフィズム）のヘッダー・タブバー・シート | `/design` |

## 必要なもの

- Node.js 24 以上（開発は v26 で確認）
- それ以外のインストールは不要です（ローカルのDBは組み込みPostgreSQLを使います）

## ローカルでの起動

```bash
npm install
cp .env.example .env.local     # 初回のみ（中の ADMIN_PASSWORD は変更してください）
npm run db                     # 別のターミナルで起動したままにする（組み込みPostgreSQL）
npm run db:migrate             # DBのテーブルを作成・更新
npm run seed                   # 初期データ（お題の候補・初期管理者）を投入
npm run dev                    # http://localhost:3000
```

`npm run seed` を実行すると、`.env.local` の `ADMIN_EMAIL` / `ADMIN_PASSWORD` で初期管理者が作られます（管理者が1人もいない場合のみ）。
管理者は、ヘッダーの盾のアイコンから管理画面を開けます。ほかのユーザーを管理者にするのは、管理画面の「アカウント」からできます。

> カメラはブラウザの制約で **HTTPS（または localhost）でしか使えません**。スマートフォンの実機で確認するときは、
> 後述の Vercel にデプロイした URL を使うのが簡単です。

## デバッグモード

`DEBUG_MODE=true` のとき、ログインしたすべてのユーザーのヘッダーに虫のアイコンが出て、`/debug` を開けます
（`false` のときはデバッグ用の API もすべて 404 になり、仮想時計も無効になります）。

| 項目 | できること |
| --- | --- |
| 時計 | アプリの中の時刻だけを進める（次の朝5時の30秒前へ、+1時間〜+1週間、日時指定、元に戻す）。お題の切り替えやイベントの期間を待たずに確認できる |
| お題 | 任意の内容・表示テンプレートのお題を今すぐ開始、ランダムに開始、今のお題を終了 |
| イベント | 用意された絵・マス目で今すぐ開始、テスト用ユーザーの写真でマスを埋める（5マス／全部で完成）、終了、「不定期の自動開催」を今すぐ発生 |
| テスト用のデータ | テスト用ユーザーが今日のお題に投稿し、いいね・コメント・フォロー・閲覧を付ける。自分の投稿への通報（自動非表示の確認）、まとめて削除 |
| ユーザーの切り替え | ログインし直さずにテスト用ユーザー／テスト管理者として操作し、画面上部の「元に戻る」で戻る |
| 端末・カメラ | ブラウザの対応機能の一覧、カメラの手動設定への対応の調査、疑似カメラ（カメラのない環境でも撮影の流れを確認）、サンプルのRAW（DNG）、フィードの並び順の内訳表示 |
| 仕様の確認リスト | 仕様書の17項目それぞれの確認のしかたと、確認済みの印（端末に保存） |
| 自己診断 | サーバー側の12項目（DB・画像の保存・写真の処理・お題の切り替え計算・閲覧制限・色の判定・検索・パスワードなど）をその環境で実行 |

> デバッグモードでは、だれでも時刻を動かしたり、テスト管理者として管理画面を使ったりできます。
> **一般に公開する環境では必ず `DEBUG_MODE=false` にしてください。**

## カメラ・RAW について（端末・ブラウザごとの違い）

- **RAW**: ブラウザからセンサーの生データを取り出す方法がないため、RAWファイル（DNG・CR2/CR3・NEF・ARW・RAF・ORF・RW2 など）を
  撮影画面の「RAW 取り込み」から取り込み、ブラウザ内（LibRaw / WebAssembly と WebGL2）で現像します。
  センサーのデータを展開できない形式は、ファイルに埋め込まれたプレビュー画像を使って現像します。
- **シャッタースピード・ISO**: Image Capture API に対応した端末（主に Android の Chrome の一部機種）でだけ手動で設定できます。
  iOS の Safari・Chrome や Firefox では手動設定ができないため、通常の撮影になり、撮影画面にそのことを表示します。
- **絞り（F値）**: Web から操作する手段がなく、スマートフォンのレンズもほぼ固定絞りのため、どの端末でも設定できない旨を表示します。
- 対応状況は `/debug` の「端末・カメラ」→「カメラの手動設定への対応を調べる」で、その端末ごとに確認できます。

## デプロイ（Vercel + Neon + Vercel Blob）

1. このリポジトリを GitHub に push します。
2. [Vercel](https://vercel.com) で「Add New → Project」からリポジトリを選びます（Framework は Next.js のまま）。
   ビルドは `package.json` の `vercel-build`（ワーカーの生成 → DBのマイグレーション → 初期データの投入 → `next build`）が自動で使われます。
3. プロジェクトの「Storage」で **Neon（Postgres）** を作成して接続します（`DATABASE_URL` が自動で設定されます）。
4. 同じく「Storage」で **Blob** を作成して接続します（`BLOB_READ_WRITE_TOKEN` が自動で設定されます）。
5. 「Settings → Environment Variables」で次を設定します。

   | 名前 | 値 |
   | --- | --- |
   | `STORAGE_DRIVER` | `blob` |
   | `ADMIN_EMAIL` | 初期管理者のメールアドレス |
   | `ADMIN_PASSWORD` | 初期管理者のパスワード（十分に長いもの） |
   | `DEBUG_MODE` | 動作確認の間は `true`、一般に公開するときは `false` |

6. 「Deploy」します。初回のビルドでテーブルの作成と、お題の候補・初期管理者の登録が行われます。
7. 公開された URL を開き、初期管理者でログインします。`DEBUG_MODE=true` なら `/debug` の「自己診断」で、
   DB と Blob への保存がその環境で動くことを確認できます。

## 環境変数

| 名前 | 説明 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL の接続文字列（ローカルは `npm run db` の組み込みPostgreSQL、本番は Neon） |
| `TEST_DATABASE_URL` | 統合テスト用のDB |
| `STORAGE_DRIVER` | 画像の保存先。`local`（`.data/uploads`）または `blob`（Vercel Blob） |
| `BLOB_READ_WRITE_TOKEN` | Vercel Blob のトークン（Storage の接続で自動設定） |
| `BLOB_ACCESS` | Blob ストアの公開設定。`public`（既定）または `private`（ストアを private で作った場合） |
| `LOCAL_STORAGE_DIR` | `local` のときの保存先（既定は `.data/uploads`） |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | 初期管理者（`npm run seed` で、管理者がいない場合に作成） |
| `DEBUG_MODE` | `true` でデバッグモード |

画像はどちらの保存先でも、同じオリジンの `/media/...` から配信します（位置情報などのメタデータは保存しません）。

## テスト

```bash
npm test          # 単体・統合テスト（vitest、テスト用DBを使う。npm run db が起動している必要があります）
npm run test:e2e  # ブラウザでのE2Eテスト（Playwright）
```

E2Eテストは、スマートフォンを想定した3種類（Android の Chrome = Pixel 7、iPhone の Safari = iPhone 15 の WebKit、Firefox）で
同じテストを実行します。Windows 版の WebKit にはカメラの機能がないため、iPhone ではカメラを使う2件のテストを省略しています。

### 実機での確認をお願いしたいこと

自動テストではエミュレーションと疑似カメラで確認しています。次の点は実機での確認をおすすめします。

- Android の Chrome で、実際のカメラのシャッタースピード・ISO の手動設定（対応機種のみ）
- iOS の Safari / Chrome でのカメラの許可と撮影、端末の傾きによる光の表現（傾きの許可）
- 実際のカメラやスマートフォンで撮った RAW ファイルの取り込みと現像

## 技術構成

Next.js 16（App Router・Cache Components）／ React 19 ／ TypeScript ／ Tailwind CSS 4 ／ Drizzle ORM + PostgreSQL ／
sharp（画像の処理）／ LibRaw（WebAssembly、RAWの現像）／ WebGL2（現像・表示テンプレートの効果）

## ブランチ運用

`main` ← `develop` ← `feature/<機能名>` の git-flow で開発します。
`main` と `develop` には直接コミットせず、機能ごとに `feature/*` ブランチで作業し、
仕様書の要件に沿って動作確認ができたものを `develop` にマージします。
